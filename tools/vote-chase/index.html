Precinct groups, optional: see one organizer's or one area's precincts at a time

What it is for. By default the list ranks every precinct in the district. If each organizer owns a set of precincts, or the field director thinks in counties or regions, groups let you filter the list to just those precincts, so an organizer sees the ranking inside their own turf and the headline numbers for it. It does not cut turf (that happens inside a precinct, in VAN); it assigns whole precincts to a label.

How to set it up. Click "Download a template" below: you get a spreadsheet that already lists every precinct in your data, exactly as VAN names them. Open it in Excel or Google Sheets and fill in the columns next to each precinct, for example county, organizer or region, with whatever labels you use ("Maria", "North", "Turf A"). Add or rename columns as you like. Save it as CSV and drop it here. Every column becomes a choice in the Filter menu above the list, such as "organizer: Maria". Precincts you leave blank show as "(no group)". Do this once; it stays with your data.

Score groups (buckets)

The score bands in the VAN file are grouped into buckets, highest score first. Pick the lowest band for each bucket. Tick "chase" on the buckets that should count toward the ranking. The default is five buckets on a 0 to 100 Democratic support score. For a Republican support score, rename the buckets and move the chase ticks; the arithmetic is the same.

Saving and sharing

This page keeps your loaded counts, settings and history in this browser on this computer. It does not sync to anyone else. To keep a backup, or to give a colleague the same view, click Download workspace: it saves one small file (a .json) with everything on this page, counts only, no individual voters. Anyone with that file opens this page, clicks Load workspace, and sees the same list. Loading a workspace replaces what is on the page.

    How it works, how to pull the files from VAN, and how to automate the VAN pulls

    The page reads VAN count reports on your computer and subtracts voters who have returned a ballot from voters who are registered, for each precinct and each score bucket. "Chase voters" are the voters in the ticked buckets who have not yet voted. Nothing is sent anywhere; your data stays in this browser.

    1. Save four searches in VAN, once. Use the same suppression setting on all four (for example Remove All Suppressions). Mixing settings makes "votes left" drift by a couple of percent.
      • Returned: Early Voting, voted early or absentee.
      • Returned, regular voters: same, plus Voting History: voted in the last midterm general OR the last presidential general (2022 or 2024).
      • Registered: active registered voters, no early-vote filter.
      • Registered, regular voters: same, plus the vote-history filter.
    2. For each: run the search, then Counts (VAN opens its "Counts and Crosstabs" page). Set Crosstab 1 = your support score (for example "2026: DNC Dem Party Support") and Column 1 = Precinct, set People from to My List (it defaults to Registered Voters, which is everyone in the committee), click Refresh Results, then Export To Excel. VAN does not keep these pickers with the search, so they are set each time.
    3. Drop the downloaded files on the boxes above. Files with or without the "%" columns both work. A CSV with the same layout works too.
    4. Returned pulls are daily; registered pulls are needed once and again after your state's registration deadline.

    What the page expects: a header row whose first cell is Precinct, a row of score band labels (0 to 9.99, 10 to 19.99, ..., 90+, Unknown), one row per precinct, and a Total People column and row. Precincts with zero people in a pull are left out by VAN; the page treats them as zero. A precinct name that appears twice is added together. Voters with no score show as their own "No score" group.

    Automating the VAN pulls

    Fully automated means nobody touches VAN in the morning: a small program on one campaign laptop (the runner, in the runner folder next to this page) signs in to VoteBuilder, runs the four saved searches, exports the four crosstabs, checks each one against the search's count, and writes data.js next to this page, which then shows today's numbers when anyone opens it. VAN cannot schedule a Counts export itself, so the runner drives the VoteBuilder website with a browser script, in the open: plain clicks, fixed waits, an exact schedule, nothing that pretends to be a person.

    It needs a VoteBuilder login, a laptop that stays on, Node.js, and about 15 minutes, set up once by whoever on the campaign is comfortable with a terminal: npm install, npm run setup (asks for the login, the score name and the four search names), npm run check (one visible pass), npm run service -- install (every morning). The steps, written out for that person, are in docs/automation.md; what the runner touches and which login to use are in docs/security.md; every error message and its fix is in docs/troubleshooting.md. It runs a script against VoteBuilder, so check with your VAN administrator first. If you are reading this page through a link rather than from a downloaded folder, download the folder first.

    Half-way option. A person does the four exports by hand in about five minutes and drops them on this page, or runs the converter (npm run make-data in the runner folder) to write data.js for the whole team.

    If you build your own exporter, write data.js as one line, window.VOTECHASE_DATA = {...};, where {...} is what "Download workspace" produces (the layout is in docs/data-contract.md). A data.json with the same content also works, but only when the page is served from a web server, not from a folder. Counts only: keep voter-level exports (names, VAN IDs, addresses) out of this folder.
